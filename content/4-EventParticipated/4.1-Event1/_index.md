## Session content

### Solution Architect Professional Native App

The first presentation introduced an AI-native assistant that helps Solution Architects transform BRD, PRD, SOP, and natural-language requirements into a requirement catalogue, cloud architecture options, Draw.io diagrams, Infrastructure as Code drafts, and cost estimates. Its Agentic AI workflow combines a knowledge base, Amazon Bedrock, diagram generation, and AWS pricing data so that an architect can refine a proposal conversationally instead of repeating manual preparation.

### The Hackathon Journey — 3KA

The second presentation described a 24-hour cycle of building, failing, learning, and delivering an MVP. The team created **S.H.E.P.H.E.R.D**—Smart Human-flow Evaluation, Prediction, Hazard Detection, Response, and Dispatch—to detect crowd density, track people, predict congestion, and alert venue operators. The presented stack included YOLO, ByteTrack, Amazon SageMaker, Amazon Bedrock AgentCore, Strands Agent, and a React dashboard. Key engineering constraints included latency, tracking accuracy, camera placement, and cost.

### AI-Powered Conversation Ordering

The **OneTeam Community Day** deck presented a KFC conversational-ordering bot agent. It provided an example of applying an AI agent to a customer-facing ordering workflow and highlighted the importance of combining conversation design with dependable business-system integration.

### Signal Scout

The **Signal Scout** deck supplied another solution case study for comparing problem framing, presentation structure, architecture communication, and the path from an idea to a demonstrable product.

## Personal learning and contribution

As an attendee, I reviewed the presented architectures, compared their problem–solution–impact storylines, and recorded practices applicable to the Heart Risk MLOps project:

- begin with the user pain point and measurable impact before introducing AWS services;
- use an agentic workflow only when retrieval, reasoning, generation, and iteration add clear value;
- make architecture, cost, security, latency, and failure handling part of the same design discussion;
- reduce hackathon scope to an MVP while keeping the demonstration traceable;
- explain technical architecture as a decision flow rather than a list of services.

The event strengthened my understanding of how to present an AWS solution to both technical and non-technical audiences. It also reinforced the need to connect the Heart Risk project’s SageMaker pipeline, monitoring, API, cost controls, and limitations to a clear operational story.
